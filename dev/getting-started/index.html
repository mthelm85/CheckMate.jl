    Getting Started#

    This page walks through a complete validation workflow: defining checks, running them, and acting on the results.

    The workflow#

    Using CheckMate always takes three steps:

    1. Define a CheckSet with the @checkset macro.

    2. Run it against your data with run_checkset, which returns a CheckSummary.

    3. Inspect the summary, either by reading the printed report or by querying it with functions such as failed_checks and failing_rows.

    1. Write validation functions#

    A validation function takes one value per column and returns a Bool: true when the row is valid and false when it is not.

    is_positive(x) = x > 0
valid_currency(x) = x in ("USD", "EUR", "GBP")

    2. Define a checkset#

    Group related checks into a named checkset. Each @check line has a name and a call that applies a function to one or more columns, written as symbols:

    using CheckMate

checks = @checkset "Payment Validation" begin
    @check "Positive Amount" is_positive(:amount)
    @check "Valid Currency"  valid_currency(:currency)
end
    CheckSet: "Payment Validation"
Number of checks: 2
  ▪ Positive Amount (columns: amount)
  ▪ Valid Currency (columns: currency)

    Displaying a checkset lists each check and the columns it reads.

    3. Run the checks#

    Pass any Tables.jl-compatible table to run_checkset:

    using DataFrames

payments = DataFrame(
    id       = 1:6,
    amount   = [100, -50, 200, 300, 0, 75],
    currency = ["USD", "EUR", "XXX", "GBP", "USD", "JPY"],
)

summary = run_checkset(payments, checks)
    
================================================================================
Check Summary: Payment Validation
================================================================================

✗ Positive Amount: 2 rows failed
   Row 2: amount=-50
   Row 5: amount=0
✗ Valid Currency: 2 rows failed
   Row 3: currency=XXX
   Row 6: currency=JPY

Summary:
 0/2 checks passed (0.0%)
Checks completed in 94.3 ms

    The report lists failed checks first, followed by passing checks. Each failure shows the row index and the values the check saw. Long failure lists are shortened to the first and last five rows.

    4. Act on the results#

    The summary can also be queried in code, which is useful in pipelines and tests:

    failed_checks(summary)
    2-element Vector{String}:
 "Positive Amount"
 "Valid Currency"
    failing_rows(summary)            # unique rows that failed any check
    4-element Vector{Int64}:
 2
 3
 5
 6
    pass_rate(summary)               # % of rows that passed every check
    33.33

    A common next step is to split the data into clean and rejected rows:

    bad = failing_rows(summary)
rejected = payments[bad, :]

    Using CheckMate in a pipeline

    To stop a pipeline when validation fails, use assert_valid. It runs the checks and throws a ValidationError, including the full report, if any check fails:

    summary = assert_valid(data, checks)
